# V15 PPO 架构、SFT 与强化学习执行计划

## 1. 总体路线

V15 采用以下完整训练链路：

```text
V13 best_heuristic.pt
        ↓
加载旧 Actor 权重
新增 zero-init offense projection
        ↓
阶段 A：仅预热 offense projection（15,000 steps）
        ↓
阶段 B：解冻完整 Actor 微调（30,000 steps）
        ↓
选择 V15 SFT 最优 checkpoint
        ↓
清零 Q head
40-update Q-Critic bootstrap
        ↓
Actor + Q-Critic 联合 PPO
```

PPO 主训练同时启用 Q-Critic + Seat-local Q-Boosting、Offense + Defense action
scoring、最终小局半庄排名奖励和 U-shaped SFT Reference KL。不加入 belief
auxiliary learning、EMA、critic replay、full joint trajectory、新 critic query 或整场
半庄 credit propagation。

## 2. V15 SFT 阶段

### 数据与初始化

- 直接复用 `datasets/tenhou_sft_2024_2025_encoded_40pct_v13_v16`，不重新构造或
  precompute；启动前校验 manifest、V13 contract、token schema 13、feature hash、
  完整动作覆盖及训练/验证样本数。
- 从 `checkpoints/train_riichi_v13_sft/best_heuristic.pt` 严格加载所有旧参数；新增
  `offense_projection: Linear(192,192)`，weight 和 bias 全部置零。
- 初始 V15 policy logits 必须与 V13 checkpoint 在相同输入上逐元素一致。
- SFT 全程保持 Critic、Q head 和 `value_query` 冻结，沿用 V13 的 policy CE、
  action-group loss 和 rule-teacher loss。

### 阶段 A：Offense projection 预热

- 仅 `offense_projection` 可训练，其余参数全部冻结。
- 训练 15,000 steps，batch size 512，双 GPU；学习率从 `1e-4` 经 2% warmup 后
  cosine decay 到 `1e-5`。
- 每 3,000 steps 保存 checkpoint、跑完整 validation，并跑固定 96 半庄启发式评测。
- 保存 step 0、3,000、6,000、9,000、12,000、15,000 checkpoint；以最低 validation policy CE 选择阶段 B
  初始化点，V13 零投影基线也作为候选。

### 阶段 B：完整 Actor 微调

- 解冻 token embedding、public backbone、actor backbone、offense projection 和
  policy head；Critic 分支继续冻结。
- 使用新 optimizer/scheduler 和不同 shuffle seed，从阶段 A 最优 checkpoint开始。
- 训练 30,000 steps；学习率从 `2e-5` 经 2% warmup 后 cosine decay 到 `2e-6`。
- 每 3,000 steps 保存 checkpoint、跑完整 validation，并跑固定 96 半庄评测。
- 合格 checkpoint 的 validation policy CE 不得差于 V13 基线，action-group、
  rule-teacher、合法动作和固定规则指标不得明显回归。
- 选出三个候选后，分别进行固定种子、席位轮转的 1v3、1,600 半庄 greedy 对局，
  对手为 V13 SFT；以平均分差及 bootstrap CI 为主，结合一位率、前二率、均顺、
  四位率和放铳率选择最终 V15 SFT。
- 若所有 checkpoint 均未超过或持平 V13，则停止 PPO 启动并审查 offense 融合方式。
- 阶段 A、阶段 B 与 PPO checkpoint 统一放在 `checkpoints/train_riichi_v15/` 下，
  分别使用 `sft/stage_a/`、`sft/stage_b/` 与 `ppo/` 子目录。阶段 B 的最终 1v3
  胜出模型保存为 `sft/final.pt`，作为 PPO 初始 Actor 与 SFT-KL reference。
- 最终 V15 SFT 同时作为 PPO 初始 Actor 和冻结的 SFT-KL reference。

## 3. 模型与 Q-Boosting 改造

### Actor 与 Critic

- 每个合法动作计算 `defense_hidden + offense_projection(offense_hidden)`，再送入原
  policy head。模型配置显式区分旧拓扑与 V15 offense fusion。
- Critic 保留 public state、对手暗手、未来五张 live wall、单个 `value_query` 和
  两层 critic transformer；将标量 value head 替换为 `q_head: Linear(192,241)`。
- PPO 初始化时 Q head 全零；SFT 不训练 Q head。非法动作 Q 不进入 expectation、
  loss 或指标。
- Rollout GPU 端只回传 `q_taken` 和 `expected_q`，不向 CPU 传完整 Q 向量。

### Seat-local Expected-SARSA(λ)

每条 `pending[env][seat]` 小局轨迹反向计算：

```text
delta_t = reward_t + gamma * expected_q_(t+1) - q_taken_t
trace_t = delta_t + gamma * qboost_lambda * trace_(t+1)
q_target_t = q_taken_t + trace_t
advantage_t = q_target_t - expected_q_t
```

Terminal 的下一期 expectation/trace 为 0；`expected_q` 只在合法动作上求和；
`gamma=0.99`、`qboost_lambda=0.95`。该实现是 seat-local 近似，不宣称完整复现
VRPO。参考：[GAE Falls Short in Imperfect-Information Self-Play RL](https://arxiv.org/html/2605.19235v1)。

### Learner

- Transition 用 `q_taken`、`expected_q`、`q_target` 替代 `value`、`return_`。
- Critic 仅监督实际动作：`Huber(Q(s, action_taken), q_target)`；保留 batch-std
  conditioning、`critic_public_grad_scale` 和 PPO clipped objective。
- update 1–40 仅训练 Q/critic 分支，Actor/Shared 冻结且 public critic gradient 为 0。
- update 41–1,200 联合训练，`critic_public_grad_scale=0.25`。

## 4. Reward、KL 与训练配置

- 每局继续使用 `clip(point_delta / 1000, -24, +24)`。
- 当 `end_kyoku` 与环境 `done` 同时成立时，按最终分数降序、同分 seat id 升序增加
  `[+12,+6,-6,-12]`。排名奖励只传播到最终小局，四席之和必须为 0。
- PPO 保持 `ppo_clip=0.20`、`target_kl=0.020`。
- SFT KL 在 bootstrap 为 0；联合训练从 0.005 线性降至 50% 处的 0.0005，再线性
  升至末尾 0.002。reference 使用最终 V15 SFT。
- 主训练 1,200 updates，`update_epochs=4`、长期 `kyokus_per_worker=16`；保留 V14
  学习率、entropy 和 70/20/10 对手混合，每 30 update checkpoint 与同步 1v3 评测。
- 使用独立 V15 checkpoint/history/log/eval 目录；训练使用 Conda `Mahjong-AI`、
  `CUDA_DEVICE=0,1`、`learner_gpus=2`。

## 5. 测试、监控与验收

- 覆盖 Actor zero-init 等价与梯度、V13 数据契约、V13→V15 迁移、V15 exact
  resume、Q `[B,241]`、actual-action gather、Expected-SARSA(λ)、终止边界、排名
  reward、KL 三锚点、batched inference、DDP、history pool 和 SFT reference恢复。
- 运行全部 `riichi_ppo_v1`、`RiichiEnv` 和 `riichi_lab_bot` 测试。
- 新增 Q loss/taken/target/expected、explained variance、advantage、policy-weighted
  legal-Q variance、排名/小局/总 reward、offense projection 权重与梯度监控。
- Smoke 使用 `CUDA_DEVICE=0,3`、`learner_gpus=2`、`target_kl=0.0`、
  `update_epochs=4`、`kyokus_per_worker=1`，连续三次；第一次视为 warm-up，分别报告
  后两次 elapsed、SPS、rollout/update wall time、padding、显存和 Q 指标。
- 稳定吞吐较同口径 V14 下降超过 10% 时暂停长训。全套测试、SFT 验收、bootstrap
  冻结和排名奖励计数均通过后，才启动长训。
- 长训结束后对候选做新 seed holdout，并以相同协议补评 V14 u120/u510。

## 6. 工作区约束

- 不修改 token schema、动作协议或 V13 数据缓存。
- 不破坏旧 V13/V14 checkpoint 的只读评测能力。
- 不触碰与本任务无关的 `riichi_ppo_v1_coverage.json` 删除状态。
