## 0. 一句话定位

> **在不追求 PBE 的前提下,把 PBE 的两个零件搬进深度学习框架:**
> **(1) 信念 = 对(隐藏手牌 × 对手类型)的后验,且它是"对手策略的函数"而非"局面的函数";**
> **(2) 决策 = 给定信念的期望最优。**
> 落地为:**共享层之后接一个 5 头信念网络(监督标签自模拟器上帝视角),信念 token 注入 Actor 私有网络,与策略联合训练;对手仍为 self-play(本轮不混合)。**

## 1. 理论框架

### 1.1 立直麻将 = 有限不完美信息博弈

- 公开历史:四家牌河(含时序/手切摸切/立直宣言)、副露、宝牌指示、分数;
- 隐藏状态:三家真实暗手 + 牌山剩余;
- 信息集:与公开历史相容的所有(暗手分配, 牌山)组合;
- 自然(洗牌/摸牌)全支撑 → 任何合法历史都可能走到。

### 1.2 为什么不能直接追求 PBE(已达成共识)

1. **共同知识缺陷**:PBE 要求所有玩家知道所有人的均衡策略;实战中对手未知、非理性、异质;
2. **多重均衡**:信念被钉死不解决均衡选择问题;
3. **所学非所战**:自我对弈学到的是"与自己策略一致"的均衡,不保证对外鲁棒。

**结论:放弃 PBE,采用"Harsanyi 类型化贝叶斯博弈 + 对群体分布的最佳响应(BR-to-population)"**:

```
对手类型 θ ~ D(行为策略,不要求理性)
目标      max_σ E_{θ~D, 手牌~先验}[ 收益(σ, θ) ]
```

- D 是"对手类型分布",不是均衡对象;
- 信念 = 后验 P(手牌, θ | 公开历史),由策略 σ 经贝叶斯规则生成;
- 决策 = 给定信念的期望最优(序贯理性的残留);
- **信念是 σ 的函数**:同一行为在不同策略下含义不同 → 信念必须随策略变化重新校准。

### 1.3 关于 on-path(可忽略 off-path 的依据)

- 定义:history h 是 on-path ⟺ P_σ(h) > 0;
- 若策略组合全支撑(softmax over legal actions,每个合法动作概率严格 > 0),
  则**整棵树都是 on-path**,off-path 自由度不存在,PBE ≈ 序贯均衡(SE);
- 因此本轮设计中只讨论"贝叶斯一致性处处生效"的情形,不处理 off-path 信念。

### 1.4 "行为即信号"在麻将中的含义

- 同一公开行为(如"早巡摸切 1 万""副露快""立直后不追打")在不同策略/手牌下的
  似然不同 → 信念更新 = 先验(均匀洗牌)× Π_t P_σ_opp(行为_t | 手牌, 局面);
- 这是信念网络监督学习的理论基础:标签是"当前真值",输入只有公开信息,
  行为(尤其对手的历史行为序列)是推断手牌的信号。

### 1.5 为什么不引入混合对手(本轮决定:保持自我对弈)

**支持保留 self-play 的论证**:PPO 训练轨迹中模型自身策略随时间漂移
(进攻→防守→进攻;副露多→少→少…),时间维度的多样性客观上模拟了多种风格;
且它不是"同时刻多样",而是"随迭代扫过风格带"(近似追踪学习/虚拟对弈变体)。

**已知的三个缺口(未来若失衡再处理)**:
1. **同刻同质**:任一 rollout 内四家同策略(除曾议的每座 5% 混合,本轮不做);
2. **覆盖不受控 + 遗忘**:轨迹是否真正横扫风格带无保证;PPO 最近数据主导,
   前期风格可能被"洗掉";
3. **无外部反例**:自我对弈不会自然产生"克制当前策略"的对手。

**本轮决定**:不混合对手。若将来需要,先做**风格覆盖审计**
(记录训练全程副露率/立直率/推防比/听牌速度曲线及各风格区段数据占比),
再建**多样性对手池 + 收益矩阵评测**,由数据决定混合比例,而不是固定 20%。
(注:曾议"每座位 5% 概率为 SFT/历史模型(合计 20%)"的方案,已暂缓。)

### 1.6 与元博弈框架的关系(记入,本轮不实现)

- 外层目标(理想):元博弈(PFSP + 收益矩阵加权 + exploiters)使 D 内生;
- 本轮只实现内层(信念 + 决策);元博弈留作后续,若做则先做风格覆盖审计。

## 2. 网络结构设计(V19)

### 2.1 总体架构

```
输入 O_t ──► Encoder(共享层 3 层,不变) ──► z_t(共享表示)
                      │
                      ├──► [信念网络(新增)] ──► B_t = {Hand, Shanten, Wait, Danger, Loss}
                      │            │                    │
                      │            └── token 化(每玩家 10×256)──┐
                      │                                        ▼
                      ├──► Actor 尾段(分析 token + 信念 token + query token)
                      │         │
                      │         ▼
                      │    Actor 尾段 2 层(定版,3+2+1 重排)→ π(a | z, B)
                      │
                      └──► Critic(特权:真实闭手;未来五张已删除;不被信念影响)

决策式:π(a_t | z_t, B_t),B 是模型前向的一部分(训练与推理同一条路径)。
```

### 2.2 信念网络:5 个输出头(已定版)

删减依据:Tenpai ≡ P(Shanten=0),被 Shanten 头吸收;Ukeire 是"自己手牌"统计,
与现有 `SELF_STATE_ANALYSIS` 的 advance_kind_count/advance_remaining 重复,砍。

| 头 | 输出形状 | 语义 | 标签(模拟器上帝视角) | 损失 |
|---|---|---|---|---|
| Hand | [3, 34, 5] | 三家各牌种张数分布(0..4) | 真手牌计数 | 逐格 softmax CE |
| Shanten | [3, 9] | 三家向听数分布(0..8,含听牌=0) | 真手牌总体向听(min of standard/chiitoi/kokushi,与 V18 overall_shanten 对齐) | 逐玩家 softmax CE |
| Wait | [3, 35] | 三家各牌种:是否听牌等待牌(35=34牌+N/A) | 真手牌的等牌集合 | 逐格 sigmoid BCE |
| Danger | [3, 34] | 我舍该牌被该家荣和的概率 | 反事实:真手牌下现在舍 t 是否可荣(含振听/宣发等待审慎处理) | 逐格 sigmoid BCE |
| Loss | [3, 34] | 放铳该牌的**当前手牌**预期打点 | 反事实:现在荣和 t 的分数(用 RiichiEnv 计分器),不可荣为 0 | 归一化回归(huber) |

**标签定义原则(重要)**:
- 均为**决策时刻反事实**,禁止用"最终实际打点/实际是否放铳"当标签(混入未来信息);
- Hand/Shanten/Wait 是当前事实标签,无未来泄漏;
- Danger 与 Wait 同源但多"荣和可行性"条件(振听、双荣等边界),按规则精确计算。

### 2.3 信念网络模块(默认设计,参数估算见 §2.6)

```
输入:z_pool = mean-pool(共享表示)     [B, 256]
→ Linear(256→512) + SiLU              [B, 512]   (1 个隐藏层,用户已定)
→ 5 个输出头(每个 = Linear(512→out)):
    Hand    → [3,34,5]  逐格 softmax(计数 0..4)
    Shanten → [3,9]     逐玩家 softmax
    Wait    → [3,35]    逐格 sigmoid
    Danger  → [3,34]    逐格 sigmoid
    Loss    → [3,34]    Linear + 归一化(回归)
```

注(开放):输入 z_pool 是否按玩家再池化(如"该家牌河 token 的池化")
可提升精度,列为后续可选项;v1 用全局池化。

### 2.4 信念注入 Actor(已定方案)

- **形式**:三家对手各 **10 个 256 维 token**(3×10 = 30 个),插入
  **分析 token 之后、query token 之前**;
- **生成方式**:每玩家信念向量 = 归一化/拼接手牌摘要(170 + 9 + 35 + 34 + 34 ≈ 282 维)
  → 共享转换矩阵 Linear(282→10×256) → reshape [10, 256];三家共用同一矩阵;
- **段标识**:`SEGMENT_BELIEF = 5`(复用 SEGMENT_CRITIC_FUTURE 删除后的空位,
  embedding 表保持 6 行;输入分册 D4);
- **mask 可见性规则**(扩展 `_actor_structured_layout`):

```
共享段 <-> 共享段                    双向(不变)
信念 token 读 共享段                  只读(信念 = 局面推断)
分析 token 读 共享+分析(不变);v1 不读信念(定版)
query token 读 共享+分析+SEP_ACTIONS+自己的对 + 信念(新增)
信念 token 不读 query / 分析(保持"信念不探测动作")
三家信念 token 彼此可见(建议,可选)
padding 不可见(不变)
```

- **实现注**:信念 token 是模型内部产物,不进 Rust 编码器;mask/segment 扩展以
  模型内部为主,协议契约哈希需要联动更新。

### 2.5 上下文预算与协议影响(必须处理)

- 编码器实测最大序列 164,输入重组(输入分册)后 ~158;+30 信念 token
  ≈ 188(定版 10 token/家,不做消融);
- **context_tokens 256 → 320(定版)**;
- 连带:segment 复用 5(无 +256)、`_assert_structure`/`_segment_map`
  mask 分支更新、契约哈希更新、相关单测更新。

### 2.7 保持不变的部分

- 特权 Critic(真实闭手 + value_head):**不变**;未来五张牌山输入已删除

- 推理路径:信念网络随模型前向自动执行,rollout 推理无额外管线。

## 3. 训练与损失

### 3.1 总损失

```
L = L_PPO + λ_b(t) · Σ_k λ_k L_k + λ_c · L_wait_danger
```

- **λ_b 调度**:前期较大(让 Encoder 学会可推断表示),后期减小(PPO 主导);
  建议 0.3–0.5 → 0.05–0.1;
- **L_wait_danger**:轻量软约束 `Danger_i(t) ≤ Wait_i(t) × 荣和合法掩码`(小权重);
  之所以不再做 7 头间大一致性约束:**联合训练下独立头天然趋向一致**
  (同一 encoder/共享梯度),用户已确认不采用"派生结构 + 大规模一致性"的复杂方案;
- 各头损失:Hand/Shanten 用 softmax CE,Wait/Danger 用 sigmoid BCE,
  Loss 用归一化 huber。

### 3.2 标签来源与存储

- 标签在 rollout 时由环境(模拟器上帝视角)精确生成,随 transition 存入 buffer;
- 紧凑存储估算:每行约 0.3–0.5 KB(hand 3×34 uint8、wait/danger 位打包、
  loss 归一化 float16 等),约 1.45M 行/rank → **每 rank 新增 ~0.5GB 量级**;
- 注意:标签只进训练,不入推理;存储不污染现有 SoA 传输结构(扩字段)。

### 3.3 与 PPO 的正确性关系(已澄清)

- 信念 B 是模型前向的一部分;**联合训练不破坏 PPO**:
  采样时 old_logprob 由同一模型快照产生,ratio 天然自洽;
- 若将来采用"分阶段更新(先 belief 微调,再 PPO)"的节奏,则必须遵守
  `rollout(冻结 B) → update(冻结 B) → belief 微调 → 下一轮 rollout` 的时序;
- 信念随策略演化存在反馈闭环,防振荡措施(将来需要时):EMA、降低更新频次、
  输出信念质量曲线(预测准确率 vs 迭代)。

## 4. 开放项(2026-09-05 状态:全部定版)

### 4.1 V19 输入格式优化与编码设计
(已定版,见《输入与模型编码》分册 D1–D14;原联动点清单保留备查)
- 新 segment/kind 常量、segment embedding 6→7、`_segment_map`/`_assert_structure`
  mask 分支、契约 SHA256 更新;
- context_tokens 256→320 及推理/学习的 capacity 影响;
- 信念标签如何从模拟器导出(环境侧插桩)、transition/buffer 字段扩展;
- 信念 token 在 `actor_input` 中的拼接位置与长度机制(模型内部实现,不经 Rust 编码器)。

### 4.2 actor 是否 +1 层(已定版:重排 3+2+1,见输入分册 D3)
- 现状 1 层(4-3=1);加层 +705,280 参数;
- **显存代价**:B=2048、T≈164 时每个额外 block 的保存激活约 **+2.3–3.4GB**,
  需现场实测(现峰值 34.1GB,逼近 35GB 验收线);
- 建议:先"1 层 + 信念 token",用 A/B 对照再决定是否加层;
  若加,优先对一个 block 做梯度检查点换显存。

### 4.3 信念损失梯度流向 + 转换矩阵更新策略(已定版:机制 A,见训练分册 D15/D16)
候选方案:
- (a) 全联合:一个优化器,λ_b 控制——简单,信念随策略自动演化;
- (b) 独立参数组/优化器(信念相关参数不同 LR 或周期性冻结);
- (c) 分阶段:先训信念(高 λ_b)→ 冻结 → 再训 PPO;
- (d) 转换矩阵单独处理:冻结或独立小步长(因为它决定 token 化稳定性)。
倾向:先 (a) 落地,λ_b 调度;把 (b)/(c)/(d) 作为出现训练不稳定时的备选。

## 5. 将来要做、本次不做

1. **信念输出直接加进 query(逐动作注入)**:给每对 O/D 查询行注入该动作的
   Danger/Loss(数值进 action_fusion 或 policy_mlp 输入),比"全局 token 里取"
   更直接;作为 v2 备选路径(与现 query 逐动作语义天然吻合)。

   风格覆盖审计 → 多样性对手池(SFT + 历史 checkpoint + 人工风格对手)→
   收益矩阵评测(1v3 管线复用)→ 按缺口/被利用度自适应比例(PFSP-lite),
   而非固定 20%。
3. (备忘)多假设 Hand 表示(top-K 候选)、蒙特卡洛边际化对照、
   类型条件化 value、信念随策略演化的 EMA——均为候选,未定。
