## 重点提醒（容易踩的坑）

- **`belief_public_grad_scale` 的 SFT 透传**：`sft/trainer.py` 的 `_forward_actor(model, batch)` 目前只接受两个参数；要改成 `_forward_actor(model, batch, config)`，并在训练与 `evaluate` 两处都传 config。只改 yaml 不生效。
- **belief backbone 9 个查询的排列**必须与现有 `belief_labels`/`belief_tokens` 顺序一致（默认 p=0 下家 / p=1 对面 / p=2 上家，每玩家内 q0/q1/q2 按序）；实现后用现有 fixture 或新增断言锁定顺序。
- **readout 零初始化**：`BeliefActionReadout.proj` 权重/bias 必须 `zeros_`，保证训练起步不影响策略；但训练一步后其梯度必须非空。
- **token_matrix 不经监督**：`_belief_losses` 的 loss 只用五头输出与 summary 的监督目标，绝不把 `belief_tokens` 或 `belief_readout` 的输出接入监督损失；token_matrix 只接收 actor loss（通过 30 token 路径）的梯度。
- **`belief_readout_detach` 只 detach 特征**：读出投影自身仍必须接收 actor 损失梯度（用户要求"从信念头到 actor 的映射矩阵需要被 actor 损失和梯度更新"）；SFT detach 只是阻止 actor 损失通过读出修改 belief 头/共享层。
- **host row plan**：`collate_samples` 要额外返回 `kind_row_plan`（`model/dense_embedding.compute_kind_row_plan`）与 `shared_capacity`；`_forward_actor` 把它们从 batch dict 取出传给 model，避免 GPU 同步 + 减少 torch.compile recompile。
- **torch_compile**：配置为 true 后首次编译很慢（约 1–2 分钟）属正常；不要因为编译慢而回退。若开发环境 CPU smoke，则先强制 `torch_compile: false`。
- **SFT 性能红线**：`sft/trainer.py` 当前每步调用 CPU `_binary_auc`(GPU→CPU + Python 逐元素 tie 循环)，实测约 **14ms/step**；新增指标时 AUC/条件 AUC 只允许在验证 cadence 或使用 `training/belief.binary_auc`(纯 torch)计算，禁止放回训练步；训练步只用 GPU 纯 torch 的 acc/topk/mean 指标。
- 参数量契约：`parameter_count.py` 仍要求 `7_000_000 <= total <= 7_200_000`；新架构预估约 7.11M，测试必须通过。
