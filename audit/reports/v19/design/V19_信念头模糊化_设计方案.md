# V19 信念头模糊化设计方案（2026-09-07）

> 用户决策：保留五个信念头、每玩家 3 个查询 token；把**随机性强、精确但信息
> 增益低**的 Hand 与 Wait-tile 模糊化；Shanten / Danger / Loss 保留；修改后
> 保证五头损失贡献均衡。用户选定：Hand = 花色×段位 16 组粗桶；Wait =
> 听牌 + 宽度桶 5 类。

## 1. 设计动机

- Hand 精确计数（每牌种 0..4）对目标信息量大但对**公开局面**极其不易推断：
  观测到的手牌不完整，精确计数标签本质是"难任务且错误率无法避免"。
- Wait 逐牌待牌位（34 位）同样随机性高：仅从公开信息很难确定对手在等哪几张，
  且过去实测表明即使训练后 tile 级指标仍接近随机。
- 这两个头保留"语义相似但更粗"的信息：Hand 知道"大概有哪些牌/有没有对子"，
  Wait 知道"是否听牌/听牌质量（几面）"，不追求逐牌精确。

## 2. 五个头定义（模糊化后）

| 头 | 输出形状 | 语义 | 标签 | 损失 |
|---|---|---|---|---|
| Hand | `[B,3,16,3]` | 花色×段位 16 组 × 计数桶 `{0,1,≥2}` | 16 组类别索引 | softmax CE |
| Shanten | `[B,3,9]` | 0..8 向听 | 类别索引 | softmax CE |
| Wait | `[B,3,5]` | 非听 / 1 面 / 2 面 / 3-5 面 / ≥6 面 | 类别索引 | softmax CE |
| Danger | `[B,3,34]` | 逐牌危险度 | 0/1 | sigmoid BCE（pos_weight=5） |
| Loss | `[B,3,34]` | 逐牌反事实放铳打点 | 归一化回归 | 危险正例子集加权 Huber |

- Hand 16 组：万/筒/索 × {1-3,4-6,7-9} = 9 组 + 字牌 7 组 = 16。
- Wait 宽度：非听(0), 1 面(1), 2 面(2), 3-5 面(3), ≥6 面(4)。
- 摘要维度：48 + 9 + 5 + 34 + 34 = **130**（原 282）。
- 逐动作读出保持 21 维：danger[tile] + loss[tile] + tenpai_prob +
  shanten_expected + max_danger + max_loss + **wait_width_expected**（全局，
  不再有 wait[tile] 逐牌项）。

## 3. 标签生成：只重标，不重编码

- Rust `prepare_belief_labels_batch` 仍产出精确 hand/wait；
- Python 边界 `model/belief_labels.py` 映射为模糊标签；
- 已编码 60% 数据集只需把 `belief_hand` / `belief_wait` 两个数组重写为
  `[B,48]` / `[B,3]`，其余数组（actor 序列、query、legal、shanten/danger/loss）
  原样复制；
- 新增 `riichi_ppo_v1/sft/relabel.py`，并行处理 9382+97 个 npz，输出
  `datasets/tenhou_sft_2024_2025_encoded_60pct_v19_fuzzy`；
- manifest `belief_shape` 更新为 `hand [48] / wait [3]`，并加
  `belief_label_scheme: fuzzy-v1`，`SFT_CONTRACT_VERSION` 升为
  `riichi-sft-v19-3-fuzzy`。

## 4. 五头损失贡献均衡（归一化）

每头原始损失除以**标签分布基线**，再乘 λ_k（默认 1.0）：

| 头 | 基线 |
|---|---|
| Hand CE | 标签 3 桶分布熵 |
| Shanten CE | 9 类分布熵 |
| Wait CE | 5 类分布熵 |
| Danger BCE | 正例加权最优常数 BCE |
| Loss Huber | 危险正例目标的中位绝对偏差 |

因此 λ_k=1.0 时五头贡献天然同量级；仍保留 `belief_head_weight_*` 供后续微调。
原始 loss 与归一化 loss 都写入 TensorBoard/指标。

## 5. 训练配置（用户决策）

- `epochs: 1`（1 epoch 已到边际，不再 2 epochs）；
- `batch_size: 6000`（双卡各 3000，减少随机性）；
- `log_interval_steps: 10`；
- data 路径指向 fuzzy 数据集；PPO 配置同步五头 λ=1.0、删除旧
  wait_tile / wait_danger 键。

## 6. 脚本与运行方式

- 一体化：`bash audit/reports/v19/scripts/run_v19_sft_fuzzy.sh`
  （直接调用 Mahjong-AI 环境解释器，**不使用 conda run**）；
- `--dry-run` 只打印命令；`--force` 强制重标；
- 重标工具：`python -m riichi_ppo_v1.sft.relabel --source ... --output ...`。
