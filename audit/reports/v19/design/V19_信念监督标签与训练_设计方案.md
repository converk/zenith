## 1. 梯度机制(D15/D16)

### 1.1 事实基础

- V18 的 critic 梯度**已经**回传共享层:critic 序列 = 共享表示 + 私有真手行 +
  value query,共享表示进入 critic 分支前经梯度缩放
  `shared_for_critic = detach() + scale × (shared − detach())`
  (architecture.py:566-575),现行配置 0.25;
- 60% 方案信念网络接入共享层改为**与 Critic 同构**:完整 `shared_hidden` 序列 +
  每玩家 3 个查询 token(共 9 个)→ 1 层信念 backbone,梯度回传问题与 critic
  完全同构 → **复用同一机制**(SFT 的 `_forward_actor` 已透传
  `belief_public_grad_scale`,SFT 训练同一默认 0.25,只改 yaml 不生效的缺陷已修复)。

### 1.2 两个梯度来源

| 路径 | 链路 | 处置 |
|---|---|---|
| 监督损失 | L_k → 信念头 → 逐玩家查询 → belief backbone → shared_for_belief → public_backbone | 头/backbone**满强度**;进 encoder 段缩放 ×0.25 |
| 策略梯度(旁路) | query 对注意信念 token → token → 转换矩阵 ← **detach(信念摘要)** | 策略梯度止于 `token_matrix`;不再进入五头/backbone/belief_query |
| 逐动作读出 | BeliefActionReadout(21 维特征 → d_model) → pair_hiddens → policy | SFT 与 PPO 均 detach=true(退出回传信念头/共享层);读出投影自身始终由 actor 损失更新 |

要点:重标度施加在 **shared_for_belief → public_backbone 的边界**(一处),
分支内部(头/backbone/转换矩阵)的一切梯度不缩放。策略梯度的主路径(query
直接注意共享 token)不受影响;encoder 总梯度画像 = policy 1.0 +
critic 0.25 + belief 0.25,三项耦合皆有界。

### 1.3 为什么必须回传(定版理由)

- 不回传 = probe 模式:encoder 只为 policy+value 优化,信念 backbone/查询
  边界处没有"让信念信息可读"的压力,信念头精度天然受限;
- 回传 = encoder 被"信念可推断"压力塑形,符合已定决策"联合训练、不做派生
  结构、不做大规模一致性"(信念文档 §3.1/§7);
- 密集监督干扰策略目标的风险由 0.25 的耦合比例控制(critic 同款先例)。

### 1.4 对照方案与备选(降级保留)

- 对照方案 B:单一 λ_b 乘在信念损失上(头与 encoder 同乘)——更简单,但头的
  监督强度与 encoder 干扰耦合在同一旋钮,后期调低会连"信念=σ 的函数"的
  再校准压力一起削弱 → 不采用;
- 调度(0.3→0.1):v1 恒定 0.25(critic 先例即恒定);出现不稳定再启用;
- 校准失真备选:若监控发现策略梯度扭曲信念校准(§5 信号),在信念摘要处
  detach(策略梯度止于转换矩阵),信念头退回纯监督。
  **2026-09-06 修正:该备选已转正为当前机制**——token 路径输入恒
  `detach(summary)`,且逐动作读出 SFT/PPO 均恒 detach;信念网络只由监督
  标签更新(监督单源,见《V19_信念网络策略梯度隔离_实施方案》)。

## 2. 五头监督标签(D17–D19)

### 2.1 定义表

| 头 | 输出 | 标签(环境上帝视角) | 损失 |
|---|---|---|---|
| Hand | [3,34,5] | 对手**暗手**逐牌种计数 0..4(副露为公开信息,不入目标);计数和 = 13−3×副露数,不做结构性约束 | 逐格 softmax CE |
| Shanten | [3,9] | 对手整体向听(副露计入),min(标准/七对/国士),口径与 V18 overall_shanten 对齐 | 逐家 softmax CE |
| Wait | [3,35] | 听牌时 = 待牌集合(荣和牌种);非听牌全 0 且第 35 位(N/A)置 1 | 逐格 sigmoid BCE |
| Danger | [3,34] | 决策时刻反事实:"我现在舍 t,i 能否荣和" = t ∈ i 的待牌 ∧ i 非振听(临时/永久,取环境状态) ∧ 规则可荣 | 逐格 sigmoid BCE |
| Loss | [3,34] | 反事实放铳打点 = **我方支付分数**(RiichiEnv 计分器精确计算,含本场、庄闲关系);不可荣 = 0 | huber(归一化见 D18) |

### 2.2 反事实原则与边界(D17–D19)

- **全部标签为决策时刻反事实**,禁止使用最终实际打点/实际是否放铳
  (未来信息泄漏)——信念文档 §2.2 原则的精确化;
- **里宝牌(ura dora)不计入 Loss 标签**(D18):ura 牌虽物理已定但属随机
  运气信息,计入会把运气方差引入回归目标(与已删除的 critic 未来五张同理);
  标签语义 = 当前可见信息下的反事实打点:可见宝牌指示计入,里宝不计,
  场风/自风/本场等可见事实计入;
- **跨家隔离反事实**(D19):双荣/头跳等跨家结算规则不影响标签——每家按
  "仅此一家在该舍牌上荣和"独立计算 Danger/Loss,标签间不耦合;
- Danger = (Loss > 0) 恒成立,但**独立建头、独立存储**(D23):校准监控清晰,
  且两头的预测不一致本身是 Wait-Danger 软约束的作用点;
- Danger/Wait 的差 = 振听与合法性信息,恰为已定软约束
  λ_c·L_wait_danger(预测上 Danger ≤ Wait × 可荣合法掩码)的语义基础;
- 头定义覆盖全部 34 牌种(含当前不可合法打出的 t):反事实定义与动作合法性
  解耦,推理期只查询合法动作,v2 逐动作注入时天然可用。

### 2.3 环境侧复用清单

| 部件 | 现状 |
|---|---|
| 向听计算 | RiichiEnv 已有(SELF_STATE_ANALYSIS 使用中) |
| 待牌计算 | 已有(worker.py:511 流局听牌掩码即同一计算) |
| 荣和打点 | RiichiEnv 计分器(精确分数) |
| 振听状态 | 环境已跟踪(临时/永久) |

标签插桩定版(D26):**计算全部在 RiichiEnv Rust core 完成**,作为观测 API
的扩展字段随批量观测导出(暗手计数/向听/待牌位集/逐牌可荣/打点/振听);
环境间并行由现有 batched step 结构承担,env 内打点仅对可荣牌种计算
(典型待牌 1–13 种);Python 侧只做打包存储,零标签计算开销。
实现期 profile,预算 <5% rollout 耗时。

## 3. 标签生成与存储(D22/D25)

- 生成时机:rollout 期,环境上帝视角,随 transition 写入 buffer;
  **标签只进训练,不入推理**(信念文档 §3.2 原则);
- **全程记录(D25)**:标签贯穿 PPO 训练全程、每个 rollout 都生成,无阶段性
  停点。理由:①再校准——信念 = σ 的函数,策略漂移 ⇒ 对手行为分布漂移 ⇒
  旧校准持续过时,监督是唯一跟踪信号;停标签 = 信念头冻结在旧策略的校准上,
  而策略继续消费劣化的信念 token(比无信念更糟);②与 value head 同构——
  "还要记标签吗"等价于"还要记 return 吗";③早期通道——随机初始化的头靠
  监督从噪声走向有用,策略才有"学会用信念"的前提;
- 不可替代性:纯策略梯度训练头只提供"什么有用"而不提供"什么是真",头与
  策略可能共谋塌缩到虚假信念,且信用分配需穿过 30 token + 转换矩阵、信号
  过弱;降频不可行——标签是逐 transition 的状态真值,rollout 结束后环境已
  前进,buffer 内状态无法事后补算;
- 自对弈四家均为学习智能体:每个座位的决策都生成标签(对该家而言,其余三家
  即标签对象),无一省份略;
- 紧凑存储(每行):

| 字段 | 编码 | 字节 |
|---|---|---|
| Hand 3×34 计数 | uint8 | 102 |
| Shanten 3 | uint8 | 3 |
| Wait 3×35 | 位打包 | 14 |
| Danger 3×34 | 位打包 | 13 |
| Loss 3×34 | float16 | 204 |
| 合计 | | ~336 B ≈ 0.35 KB |

- 规模(实算):`games_per_update=2048` × 每局 ~100 决策点 ≈ 20 万
  transition/update,双 rank 分摊 ~10 万/rank × 0.35 KB ≈
  **35–40 MB/rank/update**,随 buffer 滚动覆盖、非累计;存储扩字段,
  不污染现有 SoA 传输结构。
  **勘误**:信念文档 §3.2 的"1.45M 行/rank → 0.5 GB"口径混淆了 token 行数
  与 transition 数,高估一个量级,实现期按实际 buffer 复核。

## 4. 训练编排(D20–D22/D26/D27/D30)

### 4.1 总损失

```
L_total = L_PPO + Σ_k λ_k · L_k + λ_c · L_wait_danger
```

- λ_k:初始标定(2026-09-06,依据停止中的 SFT step24000 验证损失尺度,
  见 PROGRESS.md 阶段 9):hand=1.0、shanten=1.0、wait=0.25、danger=3.0、
  loss=3.0,**逐头按格数取均值**(Hand 3×34 格、Shanten 3 格、
  Wait 3×35、Danger 3×34、Loss 3×34),防止头规模失衡;终值待梯度隔离
  复训后按验证曲线确认;
- λ_c(Wait-Danger 软约束):小权重,默认 **0.05**(0.05–0.1 区间,实现期消融);
- 梯度耦合:`belief_public_grad_scale = 0.25` 作用于 shared_for_belief →
  encoder 边界(§1),v1 恒定(D16);
- **60% 条件/加权损失**(实现期定版):
  - wait = `w_t·BCE(N/A 听牌位) + w_c·BCE(34 牌,仅听牌行)`,w_t=w_c=1.0;
  - danger = `BCEWithLogits(pos_weight=5.0)`(正例加权);
  - loss = `huber(reduction='none') × (1 + 20·I(target>0))` 后求均值;
  - 新增键:`belief_wait_tenpai_weight`、`belief_wait_tile_weight`、
    `belief_danger_pos_weight`、`belief_loss_positive_weight`。

### 4.2 时序与自洽性

- **联合训练,无分阶段**:rollout(冻结快照;old_logprob 与信念 token 同一次
  前向产生,ratio 天然自洽)→ update 内 PPO epochs 联合优化;
- 转换矩阵(282→2560)仅由策略梯度训练(监督损失不经过 token 路径),
  且其输入恒为 `detach(summary)`——策略梯度止于转换矩阵,不进入
  信念五头/backbone/belief_query;作为"信念→token"接口随策略与信念
  共同演化;
- 备选节奏(信念文档 §4.3 的 (b) 独立参数组 / (c) 分阶段 / (d) 转换矩阵单独
  处理)降级为不稳定时的备选,触发条件见 §5/§9。

### 4.3 与 PPO 机制的关系(定版说明)

- V18 PPO 总损失本就是多项异质损失的和(learner.py:1292-1298):
  `loss = clip + value_coef·L_value − entropy_coef·H + sft_kl_coef·L_sft_kl`;
  信念项 `Σλ_k·L_k + λ_c·L_wd` 是其中的第五/六项监督,与 value 回归同类,
  同一优化器、一次 forward/backward/step,**无需任何 PPO 机制改动**;
- **ratio 自洽**:信念分支是 π_θ 的内部计算而非外部状态,r = π_θnew(a|s) /
  π_θold(a|s) 两边均为完整前向(各含自己的信念计算)的输出,PPO 数学原样
  适用;"信念随 θ 漂移"只是 θ 如何影响 π 的一部分;
- **实际风险与防线**:update 内 4 个 epoch,信念头被满强度监督推动,token
  内容在 epoch 间漂移,策略在"追缓慢移动的输入",实际 KL 可能大于纯策略
  参数变化所暗示的;头随机初始化的早期漂移最大。防线 = 0.25 耦合比 + §5
  监控 + §9 备选链;V18 已有"预热期只训 critic"先例(learner.py:1285-1290),
  信念预热(前 N update 不训 policy)可循此模式(§9);
- **无需 on-policy 修正**:标签是状态的上帝视角事实,与行为策略无关;行为
  策略只影响"哪些状态被访问",与 value 学习情况完全相同,每轮用最新
  rollout 数据重训,天然 on-policy;
- **采样/更新对称**:rollout 时信念 token 是模型自己的当前估计(标签不参与
  推理),头每轮修正后下一轮 rollout 自动生效,无训练/推理错位。

### 4.4 SFT 阶段信念预训练(D27)

- **SFT 数据重编码**:V19 输入协议全量变更 → Tenhou 数据集重新编码,产出
  `datasets/tenhou_sft_2024_2025_encoded_60pct_v19`;Tenhou 牌谱含全部手牌,
  五头标签在编码期以上帝视角离线生成,与 §2 同口径、复用同一套 Rust 标签
  API(D26);
- **SFT 目标 = actor BC + 信念监督联合**:
  `L_SFT = L_BC + belief_sft_coef · Σ_k λ_k·L_k (+ λ_c·L_wait_danger)`;
  `belief_sft_coef` v1 取 1.0(逐头按格均值后量纲与 BC 同级);SFT 节奏
  常量不变(每 3000 steps 验证/保存,contract.py 单点定义);
- **意义**:信念头在 SFT 期完成从噪声到可用的过渡,并在 SFT 行为分布上
  预校准——1v3 评测对手即 SFT 模型,"评测错位"风险(信念文档 §6)由此
  直接消解。

### 4.5 PPO 超参沿用(D30)

**完全沿用 v18_ppo.yaml,自包含复制进 v19_ppo.yaml,新增仅 §6 信念键**:
ppo_clip=0.20;update_epochs=2;target_kl=0.01(check_interval=8);
value_coef=0.3;entropy normalized 模式 0.014/0.006/0.002(middle_fraction

minibatch 2048 × 梯度累积 10。

## 5. 监控与评估面(D24/D28/D29)

### 5.1 训练期监控(D24)

信念 = σ 的函数(信念文档 §1.2),策略漂移必须伴随信念再校准;监控即验收。
指标(随训练步出曲线,tensorboard 注册):

| 指标 | 定义 |
|---|---|
| Hand | 逐格 argmax 精度;逐家 34 格全对率(整体精确匹配) |
| Shanten | top-1 精度 |
| Wait | 听牌二判精度(N/A 位);全位与仅听牌行条件 AUC;Precision@2/@5 |
| Danger | AUC(全局与分家);真值可荣牌 top-k 召回(k=真值可荣数);Wait≥Danger 违反率 |
| Loss | MSE/MAE(可荣子集单独统计) |
| per-head | hand/shanten/wait(含 tenpai/tile 分项)/danger/loss/wait_danger 逐项 loss 日志 |

- **SFT 训练步性能红线**:训练步只做 GPU 纯 torch 指标(acc/topk/mean/recall),
  AUC/条件 AUC 只在**验证 cadence** 计算(或复用 `training/belief.binary_auc`
  纯 torch 实现);禁止把 CPU `_binary_auc` 放回每步。
- PPO 侧训练内允许纯 torch AUC/条件 AUC(无逐元素 CPU 平局循环)。

- **失效信号**:策略漂移期(副露率/立直率等风格指标变动段)信念精度持续下滑
  → 再校准失败 → 依序启用备选:提高 belief_public_grad_scale → (摘要 detach
  已转正生效,若仍不足再校) → (b)/(c) 节奏备选。
