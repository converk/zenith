## 3. 架构细节（必须照做）

### 3.1 信念网络接入共享层：与 Critic 同构（完整序列接入，不用 mean-pool）

**现状对照（必须理解）**：

- Critic：`shared_hidden` 完整序列 + critic 私有行 + `value_query` → 1 层 `critic_backbone`（双向）→ 读 `value_query` 位置 → `value_head`。
- 信念新方案：`shared_hidden` **完整序列** + **每玩家 3 个查询 token(共 9 个)** → 1 层信念 backbone（双向，FFN=512）→ 读 9 个查询位置 → `[B,3,3,256]`（玩家 × 3 个查询）→ 五头作用于每个查询后按查询平均 → 三家摘要 `[B,3,282]` → 共享逐家五头的输出、摘要与 30 token。

**架构实现（`belief_network.py` 与 `architecture.py` 职责切分）**：

- 信念 backbone 放在 `architecture.py`（与 `critic_backbone` 同构、同属主模型）：
  - `self.belief_backbone = Decoder(belief_config, layers=1)`，`belief_config = replace(config, ffn_dim=512)`（FFN 512 而非 704，控制参数量；注意 `ModelConfig` 不参与输入协议契约，只影响 checkpoint/model_state）；
  - `self.belief_query = nn.Parameter(torch.empty(3 * 3, d_model))`（玩家主序：p0 的 q0/q1/q2, p1 的 q0/q1/q2, p2 的 q0/q1/q2），初始化为 `d_model**-0.5` 随机（与 `value_query` 同法）；
- 在 `forward` 中构造信念序列（全部向量化，禁止 Python 循环）：
  ```
  belief_total_lengths = shared_lengths + 9
  belief_sequence [B, S+9, 256]:
      [0:S]   = shared_for_belief          # shared_hidden 经 belief_public_grad_scale 缩放后的完整序列
      [S:S+9] = belief_query               # 每玩家 3 个查询，共 9 个
  mask = _bidirectional_layout(belief_total_lengths, S+9)     # 与 critic 相同的双向可见
  belief_hidden = belief_backbone(belief_sequence, ...)
  player_queries = belief_hidden[arange(B), shared_lengths[:,None]+arange(9)]   # [B,9,256]
  player_query_hidden = player_queries.view(B, 3, 3, 256)     # [玩家, 查询, d]
  ```
- `BeliefNetwork` 改为**头 + 摘要 + token 模块**（不再接收 mean-pool/`shared_hidden` 的直接输入）：
  - 输入 `player_query_hidden [B,3,3,256]`；
  - 五头均为共享逐家小头，且**对每个查询分别应用、再按查询取平均 logits**：
    - 例如 hand：`head_hand(player_query_hidden.reshape(-1,256)) → [B,3,3,170] → mean(dim=2) → [B,3,170] → view[B,3,34,5]`；
    - shanten/wait/danger/loss 同法；
  - 五头输出因此仍是 `[B,3,…]`（三个查询已通过 logits 平均融合）；
- 输出形状不变：`belief_*` 仍 `[B,3,…]`；`belief_summary` 仍 `[B,3,282]`；`belief_tokens` 仍 `[B,30,256]`；
- `token_matrix`（282→2560）**完全不动**，参数与结构不变，仍然只由 actor/policy 梯度更新，监督损失不经过 token 路径。

**参数估算**（供 `parameter_count.py` 断言参考）：

```
belief_backbone 1层(attention 163,840 + FFN 512 393,216 + norms 512) ≈ 557,568
belief_query 9×256                                 2,304
五头(256→170/9/35/34/34)                           72,474
token_matrix 282→2560                             724,480
信念相关合计                                     ≈ 1,356,826
模型总计(含 readout 5,632)                       ≈ 7,111,996
```

- 该值在 `7,000,000 <= total <= 7,200,000` 契约内。
- 三家顺序与 `belief_labels`/`belief_tokens` 现有顺序一致（p=0 下家 / p=1 对面 / p=2 上家），9 个查询按“玩家主序 × 查询序”排列；用 fixture 断言锁定；若现有顺序不同，只调 `belief_query` 与 mask 的排列，不改标签顺序。

### 3.2 BeliefActionReadout（新文件）

```
class BeliefActionReadout(nn.Module):
    def __init__(self, d_model=256, feature_dim=21): ...
    def forward(self, belief, tile_codes, *, detach=True) -> Tensor  # [B,Q,d_model]
```

- 输入 `tile_codes[B,Q]` = 每个合法动作 Query 行的 `primary_tile_code`（0=N/A，1..34），从 `actor_factors` 的 Query 尾行第 3 列提取；
- 特征（逐动作，维度约 21）：
  1. 3 家 × `danger[opp][tile]`
  2. 3 家 × `loss[opp][tile]`
  3. 3 家 × `tenpai_prob`（=1-sigmoid(wait_logits[...,34])）
  4. 3 家 × `shanten_expected`（softmax 加权和）
  5. 3 家 × `max_danger`（对 34 牌 max）
  6. 3 家 × `max_loss`
  7. 3 家 × `wait[opp][tile]`（可选，保留给后续消融；可由模型自行降权）
- `tile_code==0` 的动作（pass/无牌类）把 tile 相关项置 0，保留全局项；
- `detach=true` 时对特征张量 `.detach()` 后再进投影；`detach=false` 时按原图；
- `self.proj = nn.Linear(feature_dim, d_model)`，**权重与 bias 零初始化**（读出从 no-op 起步）；
- **本模块不接受任何监督损失**，只由 actor 的 BC/PPO 损失训练。

### 3.3 architecture.py 接入点

- `self.belief_readout = BeliefActionReadout(self.config.d_model)`；
- `forward`/`forward_actor` 新增参数：
  - `belief_readout_enabled: bool = True`
  - `belief_readout_detach: bool = True`
- `pair_hiddens = self.action_fusion(cat(offense_hidden, defense_hidden))` 之后：
  ```
  if belief_readout_enabled:
      readout = self.belief_readout(belief, tile_codes, detach=belief_readout_detach)
      pair_hiddens = pair_hiddens + readout
  ```
- 提取 `tile_codes` 的式子（原序列不含信念 token，Query 尾行仍在原 `actor_factors` 中）：
  ```
  offense_cols_orig = actor_lengths[:,None] - 2*pair_counts[:,None] + 2*arange(Q)[None,:]
  safe = clamp(offense_cols_orig, 0, T-1)
  tile_codes = actor_factors[batch_rows, safe, 3].long()
  ```
- 由于零初始化，未训练/未更新时读出不影响 logits；训练后必须进入 `output` 的梯度图（用于 channel 验证）。
- 归一化/`belief_public_grad_scale` 逻辑保持：**先 detach+重标度 `shared_for_belief`，再构造 belief_sequence**。

## 4. 训练目标与指标重构

### 4.1 损失（SFT 与 PPO 同构）

```
L = policy_term + belief_sft_coef * Σ_k λ_k L_k + λ_c L_wait_danger
```

| 头 | 新损失定义 |
|---|---|
| hand | 不变：逐格 softmax CE |
| shanten | 不变：逐家 softmax CE |
| wait | `w_t * BCE(N/A 听牌位) + w_c * BCE(34 牌, 仅听牌行)`；`w_t=1.0, w_c=1.0`；听牌行 = `wait_labels[...,34]==0` |
| danger | `BCEWithLogits(..., pos_weight=5.0)`（正例加权，供决策校准） |
| loss | 加权 huber：`huber(reduction='none') * (1 + 20 * (target>0))` 后求均值 |
| wait_danger | `λ_c=0.05` 不变；新增违反率指标 |

新增配置键：

```yaml
belief_wait_tenpai_weight: 1.0
belief_wait_tile_weight: 1.0
belief_danger_pos_weight: 5.0
belief_loss_positive_weight: 20.0
```

### 4.2 指标（训练 + 验证 + PPO 都注册；**SFT 训练步只做低成本 GPU 指标**）

```
# 训练步(每 step,GPU-only,无 CPU 同步/无 argsort):
belief_wait_tenpai_acc          # N/A 位二判
belief_loss_conditional_mae     # 仅 danger=1 格
belief_danger_recall_at_topk    # 只能用纯 torch 实现；若需 CPU 循环则挪到验证
belief_wait_precision_at_2      # 仅听牌行、top-2(纯 GPU 可做)
# 验证 cadence(每 3000 步)与 PPO 训练内:
belief_wait_conditional_auc     # 仅听牌行、34 牌
belief_danger_auc(保留)
belief_wait_danger_violation    # danger_prob > wait_prob * danger_label 的比例
belief_loss_hand / shanten / wait / danger / loss / wait_danger   # per-head loss
```

**性能红线**:SFT trainer 当前 `_belief_metrics` 每步调用 CPU `_binary_auc`(GPU→CPU + Python 逐元素 tie 循环),实测 **~14ms/step**,必须消除:
- 训练步内只用 GPU 纯 torch 指标(acc/topk/mean/sum),禁止调用 `_binary_auc`;
- AUC/条件 AUC 只在**验证 cadence** 计算,或复用 `training/belief.binary_auc`(纯 torch,无逐元素 CPU 循环);
- 新增的 3 个查询/1 层 belief backbone 已经增大计算量,不能让每步 CPU 指标把收益吃掉。

### 4.3 SFT 训练开关

- `_forward_actor(model, batch, config)` 改为读取并透传：
  - `belief_public_grad_scale`（新键，默认 0.25）
  - `validate_structure`（新键，默认 false）
  - `belief_readout_enabled` / `belief_readout_detach`
  - `kind_row_plan` / `shared_capacity`（由 collate 计算，稳定 torch.compile）
- `collate_samples` 增加 host 侧：
  - `kind_row_plan = compute_kind_row_plan(actor_factors_np)`
  - `shared_capacity = max 每行 segment==SHARED 的有效行数`
- `torch_compile: true` + `validate_structure: false` 一起用；evaluate 走同一 `_forward_actor`。
- **batch 不要再调大**:实测单卡本地 B=512 时 0.134s/step(约 3,820 samples/s/卡),本地 B=1024 时 0.301s/step(约 3,400 samples/s/卡),吞吐反而下降;保持全局 B=1024(双卡各 512)。
- 可选(需机制文档同步,不强推):验证 cadence 3000→6000 可再省 ~5%;先不动版本节奏。
