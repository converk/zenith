## 2. V19 输入序列总布局

```
—— Rust 编码器产物(shared_capacity 内,SEGMENT_SHARED)——
[BOS]
[TABLE]                  全局:场风/局数/本场/供托/亲家/自己座/决策模式/刚摸牌/
                         自家立直状态/宝牌指示×5(型+红)/own_rank
                         + numeric:四家分数、与下/对/上分差
[SEP_SELF_HAND]→[SELF_HAND]×n(逐牌种:型/张数/红/是否刚摸/立直锁定)
[SELF_STATE_ANALYSIS]    向听四系/进张·待牌聚合计数/三种振听/役·宝牌/符数
[SEP_PLAYERS]→[PLAYER]×4 纯静态卡(D9 收敛,§3.3)
[SEP_RIVERS]
  [SEP_SHIMOCHA_RIVER]→[RIVER_DISCARD]×n→[RIICHI_CARD]   ← 立直卡紧随该家河块
  [SEP_TOIMEN_RIVER]  →[RIVER_DISCARD]×n→[RIICHI_CARD]
  [SEP_KAMICHA_RIVER] →[RIVER_DISCARD]×n→[RIICHI_CARD]
[SEP_MELDS]→[MELD]×n     四家齐全(+meld_turn+called_tsumogiri)
[SEP_TILE_STATE]→[TILE_STATE]×34   每牌种统一状态卡(可见性/宝牌/安全性/进张待牌标记)
[SEP_OPPONENT_ANALYSIS]→[OPPONENT_ANALYSIS]×3   行为统计卡(D9 收敛)
[SEP_ACTIONS]→[O/D]×2n   每合法动作一对,尾部连续尾窗(契约不变)
—— 模型内部注入(actor backbone 输入,不经 Rust 编码器)——
[BELIEF]×30              3 家×10 token,SEGMENT_BELIEF=5,分析后 query 前
—— critic 独立序列 ——
[SEP_CRITIC]→[CRITIC_HAND]×n   全家真实闭手(未来五张已删,D1)
```

各分区语义一句话:什么局势(TABLE/PLAYER)→ 我有什么(SELF)→ 发生过什么
(RIVER/RIICHI/MELD)→ 还剩什么(TILE_STATE)→ 对手是什么人(ANALYSIS)→
我能做什么(ACTIONS)→ 别人可能拿什么(BELIEF)。

### 2.1 重组四原则(D7)

1. **簇内保序+紧凑**:河块内序列顺序=打牌顺序,RoPE 距离 ∝ 巡目差,出牌时序
   不再单独依赖行内字段;
2. **天然配对就近**:每家的河/立直卡相邻;分析卡贴近其消费端;动作区在尾端;
3. **三层信息流保持不动**:原始共享段 → 分析段 → 动作段的单向层级与现有
   mask 骨架不碰,重组只动布局不动权限;
4. **漂移的本质部分用字段补偿**:河长变化导致河→动作区距离漂移是本质的
   (河长=局面进度),由 `river_index`/`age_bucket` 字段补偿;V1 不引入分区
   位置编码等新机制。

### 3.4 定稿修正记录(重要:对讨论稿的三处修正)

写本文档时逐行核对了 Rust 编码器与 schema,修正讨论中的三处判断:

- **修正 A:`is_advance`/`is_win` 保留在 TILE_STATE。**
  `SELF_STATE_ANALYSIS` 的 advance_kind_count(35)/advance_remaining(101)是
  **标量聚合计数**,不含逐牌隶属关系;逐牌"哪些牌种是进张/待牌"的集合
  **只存在于 TILE_STATE 标记**(且进张/待牌牌种大多不在自家手牌,无法挂到
  SELF_HAND 行)。移出会真实丢失信息,违背"信息足够"前提 → 保留。
- **修正 B:`self_discard_count`/`self_ever_discarded` 保留在 TILE_STATE。**
  自己的河不逐张入模(河循环仅三家),这两个字段(+三种振听 flag)是
  "自己弃牌历史"的唯一载体;模型需要它来对齐"对手眼中的我"(二阶博弈)。
  → 保留。
- **修正 C:MELD 增加 called_tsumogiri(2)。** 被鸣锚行删除后,"供牌者打的是
  摸切还是手切"随锚行消失(该牌已不在河中),须在 MELD 行补上;
  meld_turn 与立直巡目联动可恢复"立直阶段被鸣"等派生信息。可接受的微小
  损失:被鸣牌在河中的停留时长不再单独可恢复。

净效果:原清理 #4"TILE_STATE 纯资源化"缩减为**仅可见性字段收敛**;
TILE_STATE 最终字段:tile_type/self_concealed_count/self_discard_count/
self_ever_discarded/unknown_count/all_seen/dora_multiplicity/is_dora/
round_wind_match/seat_wind_match/red_five_kind/is_advance/is_win/
genbutsu×3/suji×3/wall_class/dora_neighbor。

## 4. 保留不变的契约

### 4.1 mask 骨架与 pair 隔离

- 共享段 ↔ 共享段双向;分析读共享∪分析;每个 query pair 读
  共享∪分析∪SEP_ACTIONS∪本对(新增:∪信念);**不同 pair 互不可见**;
  padding 不可见。
- pair 隔离的理由(定版):①保证 logit(a|s) 是 (状态,动作) 的函数,与合法集合
  组成无关;②动作间竞争由终点 softmax 一次完成,跨 pair 注意力与之冗余;
  ③单选决策无内在跨动作交互(未来交互归 critic);④逐 pair 独立计算,
  embarrassingly parallel、compile 友好。
- 信息在动作间的合法流动仅两条:所有 pair 读同一份共享上下文(含信念块);
  终点 softmax 归一化竞争。

### 4.2 策略读出机制(备查,V19 零改动)

```
尾部连续 2×pair_count 行 = query 行(O 先 D 后相邻成对,canonical 契约,
_assert_structure fail-closed 校验,architecture.py:474-487)
→ 算术索引收集 offense/defense hidden(无效槽 clamp 取占位,where 置 0,
  architecture.py:492-510)
→ action_fusion(concat(O,D):512→256+SiLU)
→ policy_mlp(RMSNorm→256→256→SiLU→256→1):每 pair 一个标量,权重全共享
→ scatter_add 进 raw[B,241](query_action_ids 行内升序且唯一,:512-518 校验)
→ 合法掩码 -inf → 输出 policy_logits(未归一化)
→ 下游 softmax:采样与 old_logp 在 inference.py:627/634,
  PPO 更新在 learner.py:308/1245;归一化只在合法集合上进行
```

要点:模型输出是固定 [B,241] logits;变长 pair 集合由"逐 pair 共享打分 +
按 id 散射"吸收;logit 标量相互独立是刻意的,softmax 是耦合步。

### 4.3 嵌入机制(D10,真实维度备查)

- SIMPLE 类:逐字段独立 embedding 表(16 维)→ concat 统一宽度 → 共享单层
  投影 → 256;
- DENSE 类:逐字段独立 embedding 表(32 维,code 0 零贡献)+ 数值槽专属投影
  → concat → 共享投影 → 512(dense_fusion_dim)→ 共享 gated/SiLU MLP
  (512 → 2×512 门控 → 256);
- 分隔符:类别专属 learned embedding;segment(6 行)/kind(128 行)embedding
  加性组合;
- 字段增删只改各字段表大小,机制零改动。SEGMENT_BELIEF=5 不扩表。

### 4.4 其他不变

- 编码哲学:当前局面快照;MJAI 事件仅用于同步/生命周期/动作执行,不作输入;
- 特权 critic:真实闭手(全家)+ value_head + value query;
- 共享层 3 层;RoPE 全局绝对位置 + base 10k;评估机制常量(1v3 等)不动;
- tiles_left/envs.walls() 的**环境侧能力**保留(规则判定与将来信念标签插桩)。

## 6. 信念 token 注入(与《信念网络设计方案》§2.4 的衔接)

- 30 token = 3 家 × 10,由信念分支(完整 shared_hidden + 每玩家 3 查询共 9 个
  经 1 层 backbone 读出 → 五头逐查询平均 → 三家摘要)经三家共享转换矩阵
  Linear(282→2560) 生成;
- 注入点:actor backbone 输入序列,分析行之后、query 尾窗之前;**最后一个
  信念 token 距第一对 query 恒距 1**,到第 k 对 query 距离 2k+1 —— 对所有 k
  严格近于任何其他块(策略头只读 query,故信念是离全部消费者最近的块);
  该不变式与 pair 数 n 无关;
- mask:信念 → 只读共享段;query → 读信念;信念 ↔ 信念互见;分析 v1 不读
  信念(定版 D32,训练分册);pair 隔离不变;尾窗契约不变;
- 无 SEP 分隔行:SEGMENT_BELIEF=5 的 segment 嵌入即身份标记;不进 Rust
  编码器,`_assert_structure` 如需锚点在实现期加;
- 协议影响:信念是"对手策略的函数",注入与联合训练细节以信念文档为准。

## 7. 层数重排与参数核算

- ModelConfig:`layers=5`(actor_backbone = 5-3 = 2 层)、`critic_layers=1`;
  总 block 数 3+2+1 = 6 与 V18 相同,每 block 705,024,**层数重排参数增量为 0**;
- V19 总参数 ≈ V18 5,801,810 + 信念网络 565,582 + 转换矩阵 724,480 ≈ **7.09M**

  <1 万,以 `parameter_count.py` 实测为准);

  且 +1 block 是大头,critic 减层在短序列上节省有限;B=2048 需实测,
  验收线 35GB,预案 = 对 actor 一个 block 开梯度检查点。
